Fault kinds

This page describes every fault the nemesis can inject, the parameters the planner draws for it, and the rules that decide which faults may run at the same time. synth kinds prints the same catalog from the binary you have.

Catalog

Section titled “Catalog”

Disruptive kinds take a node or pod out of service. They count against faults.maxNodeFaults and never overlap on one target.

Kind Mechanism Antithesis name Disruptive Parameters
node.pause docker pause on the node container: every process freezes, the node stays on the network pause yes none
node.kill docker kill -s KILL; docker start after the duration. Every pod on the node dies. kill yes none
node.stop docker stop -t 5 (graceful); docker start after the duration stop yes none
node.throttle docker update --cpu-quota: caps the node’s CPU throttle no cpus 0.02–0.3 (share of one CPU)
node.partition iptables DROP between groups of nodes, from a helper sharing each node’s network namespace partition no groups; asymmetric (20% of draws)
node.netem tc netem on the node’s eth0 clog no delay_ms 20–800, jitter_ms 0–200, loss_pct 0–30
pod.kill force-delete (--grace-period=0); the controller recreates the pod kill yes (for 5 s) none (instant)
pod.pause SIGSTOP to every process in the pod’s cgroup, SIGCONT after pause yes none
pod.partition iptables DROP inside the pods’ network namespaces, through the synthesis-agent DaemonSet partition no groups; asymmetric (20% of draws)
pod.netem tc netem inside the pod’s network namespace clog no as node.netem
pod.clock Chaos Mesh TimeChaos shifts one pod’s clocks skip no offset_s ±0.05–120; monotonic (50% of draws)
pod.clock_all the same skip on every fault-target pod at once skip no as pod.clock

Durations are drawn log-uniformly between faults.minDuration and faults.maxDuration, so short faults are more common than long ones. Numeric parameters with wide ranges (delay, clock offset) are also drawn log-uniformly.

Partitions

Section titled “Partitions”

A partition splits the eligible targets, shuffled, into two groups (three, a quarter of the time, when there are at least four targets); not every target has to be in a group. Each member drops traffic from every member of the other groups. An asymmetric partition only installs the rules on the first group, so traffic into that group is dropped while its own packets still go out.

Clock skips

Section titled “Clock skips”

Clock skips are opt-in: all, node.* and pod.* do not include them, so name pod.clock or pod.clock_all in faults.enabled. Doing so makes synth up install Chaos Mesh 2.8.4 with helm.

  • Every skip moves CLOCK_REALTIME. Half of them also move CLOCK_MONOTONIC, which is what elapsed-time checks and timeouts read.
  • Only processes running at injection time are shifted. Processes started later, including test commands run with kubectl exec, see the real clock.
  • The skip works through vDSO patching, so it also reaches static Go binaries.
  • After applying, synth checks that every target container reports the skew and that none restarted; after reverting, that the skew is gone.
  • On arm64 nodes clock faults are skipped, because released arm64 chaos-daemon images crash the processes they inject. SYNTH_CLOCK_ARM64=1 forces them.

Choosing kinds

Section titled “Choosing kinds”

faults.enabled takes kind names and wildcards:

Entry Expands to
all every kind except the clock kinds
node.* the six node kinds
pod.* pod.kill, pod.pause, pod.partition, pod.netem
pod.clock itself (opt-in)

With faults.swarm: true, each timeline keeps each enabled kind with probability ½ (and at least one).

Targets

Section titled “Targets”
  • Nodes. faults.nodes: agents (the default) allows the agent nodes; all also allows servers other than the first. server-0 is never faulted: it runs the control plane, the workload pod and synthesis’ helpers.
  • Pods. Pods matching faults.podSelector (synthesis.dev/fault-target=true) in the namespaces your manifests put pods in.
  • A kind is left out of a timeline when it has too few targets: one for most kinds, two for partitions.

synth chooses every target itself. No tool-side randomness is used (no “pick one pod” modes), so plan.json is a complete record of what the nemesis did.

Overlap rules

Section titled “Overlap rules”

The planner draws arrivals as a Poisson process at the swarm’s intensity and drops any fault that would break these rules:

  1. At most faults.maxNodeFaults disruptive faults are active at once.
  2. Two disruptive faults never hit the same target at the same time.
  3. Only one partition per layer: a node.partition never overlaps another node.partition, nor a pod.partition another pod.partition.
  4. Two clock skips never overlap on the same pod (Chaos Mesh would add them up).

Mutated, spliced and hand-written plans are normalised with the same rules. Workload-requested faults are checked against them too, and against the planned faults that are active.

When a planned fault is skipped

Section titled “When a planned fault is skipped”

The nemesis records every planned fault as applied, failed or skipped in events.jsonl and the report. A fault is skipped when:

  • a quiet period is active, because a command ran $ANTITHESIS_STOP_FAULTS <seconds>; the nemesis heals what is active and injects nothing until the period ends;
  • it overlaps a workload-requested fault under the rules above;
  • its target is unavailable, for example a pod whose node is down, or a clock fault on an arm64 node;
  • the driver phase ended first (cancelled).

A failed fault (for example, a partition member without an IP yet) makes the “Faults applied cleanly” check fail. That check is informational, not a finding.

Hand-written scenarios

Section titled “Hand-written scenarios”

synth run --plan FILE accepts a plan in the same JSON shape plan.json uses. Only faults is required; targets must be current node container names (k3d-<cluster>-agent-0) or pods (namespace/name):

at and duration are seconds from the start of the driver phase. The repository’s examples/kv/scenarios/ has a scenario with every planned kind and one with clock skips.

Antithesis faults not implemented

Section titled “Antithesis faults not implemented”

Thread pausing has no equivalent yet. See Antithesis’ fault types for the platform’s full list.
